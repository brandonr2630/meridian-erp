# Edit Bill (AP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an admin edit a Draft or Approved AP bill's line items and notes (header fields stay locked), with a required reason, a relational archive of the prior lines, and an "Edits" tab in the existing bill History modal.

**Architecture:** `index.html` is a single-file vanilla JS app — no build step, no test runner (see project `CLAUDE.md`). The New Bill modal (`#modal-bill`) is reused in an "edit mode" (header fields disabled, line items + notes + a new required Reason field editable) rather than building a second modal. Saving an edit archives the bill's current `bill_lines` into a new `bill_lines_archive` table (tagged with a `bill_edit_events` row capturing who/when/why), then deletes and reinserts the lines exactly like `saveBill()` already does, then re-runs the existing Phase-1 `jcSyncBillCatalogOnApproval()` catalog-sync logic. All schema changes go through the Supabase MCP (`apply_migration`) against project `fcagxvjxfqqkmuposmcb`. Verification is manual (via `execute_sql` and the app itself) since this codebase has no automated test suite — do not introduce one as part of this plan.

**Known constraint carried into this plan:** bill lines with `item_category = 'equipment'` never carry an `item_id` (Phase 1 only supports *creating* a new Equipment asset at approval time, never linking to an existing one — see `jcOnBillLineCategoryChange`'s equipment branch). `saveBill()`'s line-collection logic unconditionally rebuilds a `_newEquipment` object whenever the Equipment category is selected on a line, which would create a **duplicate** Equipment asset every time an edit is saved if that state were blindly re-selected. To avoid this, the edit-prefill step deliberately does **not** re-check "Link to Inventory" for lines whose `item_category` is `'equipment'` — those lines revert to unlinked (no `item_category`) if resaved without the admin manually re-linking them. This is an intentional, documented behavior, not an oversight.

**Tech Stack:** Vanilla JS, Supabase (Postgres + PostgREST), no bundler.

**Spec:** `docs/superpowers/specs/2026-07-05-edit-bill-design.md` — read this first if anything below is ambiguous.

create table bill_edit_events (
  id uuid primary key default gen_random_uuid(),
  bill_id uuid not null references bills(id) on delete cascade,
  edited_by uuid references auth.users(id) on delete set null,
  edited_at timestamptz not null default now(),

create policy "authenticated users full access" on bill_edit_events
  for all to authenticated using (true) with check (true);
create index idx_bill_edit_events_bill_id on bill_edit_events(bill_id);

create table bill_lines_archive (
  id uuid primary key default gen_random_uuid(),
  edit_event_id uuid not null references bill_edit_events(id) on delete cascade,
  original_line_id uuid,
  description text,
  quantity numeric,
  unit_price numeric,
  amount numeric,
  line_order integer,
  item_category text,
  item_id uuid,

alter table bill_lines_archive enable row level security;

  for all to authenticated using (true) with check (true);

function jcPrefillBillLineLink(lid, category, itemId) {
  // Equipment links are create-a-new-asset-once, at approval time (see jcOnBillLineCategoryChange's
  // equipment branch — there is no "select existing equipment" path). Re-checking this box on edit
  // would cause collectBillFormLines() to rebuild a fresh _newEquipment object and create a *second*
  // asset on every edit-save. So equipment-category lines are intentionally left unlinked on prefill —
  // an admin who wants to (re-)link one must explicitly check the box and fill in the fields again.
  if (!category || category === 'equipment') return;
  const checkbox = document.querySelector(`#${lid}-link input[type="checkbox"]`);
  if (!checkbox) return;
  checkbox.checked = true;
  jcToggleBillLineLink(lid, true);
  const catSel = document.getElementById(lid + '-cat');
  catSel.value = category;
  jcOnBillLineCategoryChange(lid);
  if (itemId) {
    const meta = BILL_LINE_CATEGORIES.find(c => c.value === category);
    const idx = (jcConfig[meta.cfgKey] || []).findIndex(r => r.id === itemId);
    if (idx > -1) {
      const itemSel = document.getElementById(lid + '-item');
      if (itemSel) { itemSel.value = String(idx); jcOnBillLineItemChange(lid); }
    }
  }
  // If itemId is null but category is set, this line was linked to a *newly created* catalog item at
  // original approval time whose id was never written back to bill_lines (a pre-existing Phase 1 gap,
  // out of scope here). The category is still preserved above; the item dropdown is simply left on its
  // default "Select existing item…" option since we have no id to match against.
}

    })));

      subtotal, tax_rate: taxRate, tax_amount: taxAmt, total,
      balance_due: total, notes
    });

    _billsWithEditHistory.add(billId);
