# CLAUDE.md — Meridian ERP

Live URL: `erp.terranresources.com` · Repo: `brandonr2630/meridian-erp`

## Architecture

**Single-file app** — the entire application is `index.html` (~20,350 lines of inline CSS + JS). Never edit `index2–5.html`; those are archives.

- **Backend:** Supabase, called via a thin fetch wrapper. All DB access goes through `sb()` → `sbGet / sbPost / sbPatch / sbPatchWhere / sbDelete / sbDeleteWhere`.
- **Auth:** Supabase JWT. Session persisted to `localStorage` and restored on load by `tryRestoreSession()`.
- **Multi-company:** every record scoped to `currentCompany.id`. Company switcher in topbar; `switchCompany(id)` reloads view data.
- **Navigation:** `navigate(view)` sets `currentView` and calls `loadViewData(view)`.
- **State:** global vars declared at `// ── STATE ──` (~line 3373): `currentUser`, `currentCompany`, `accounts`, `contacts`, `journalEntries`, `bankAccounts`, etc.

## Audit log rule

`job_audit_log` rows with these action types are written only by SECURITY DEFINER database functions, and a browser session may not insert them (the D0c insert policy refuses them): `baseline_locked`, `baseline_reset`, `visibility_changed`, `schedule_exported`, `schedule_imported`. The web app itself writes only `job_saved` and `job_deleted`. If a database function starts writing a new action type, add it to the list in the policy in a NEW migration (see `supabase/migrations/*_d0c_audit_reserved.sql`) and run `node scripts/verify-audit-reserved.mjs`; it fails when a function-written type is not reserved, when the writer is not SECURITY DEFINER, or when the app writes a reserved type.

## Roles

`super_admin` > `admin` > `sales` > `user`. Finance modules (AP, Bank, CoA, Journal, Reports) are admin-only. Check `canPost()`, `canVoid()`, `canFinance()` before rendering controls.

## Keep checkouts in sync

The root checkout (`z-master`) is not updated by PRs and goes stale. Treat it as read-only: do all work in `.worktrees/<name>` branches cut from `origin/master` (`git worktree add --no-track -b <branch> .worktrees/<name> refs/remotes/origin/master`). Before reading `handoff.md` or starting work, run `git fetch -q && git status -sb`; if behind, `git merge --ff-only origin/master`. A `SessionStart` hook in `.claude/settings.json` warns when `origin/master` is ahead. `handoff.md` ends each session with the master SHA so you can compare it to `git rev-parse origin/master`.
